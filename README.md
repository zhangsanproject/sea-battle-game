# 海战霸主

基于 TypeScript、Vite 和 Three.js 的 3D 海战 Roguelike 原型。玩家驾驶战船自动炮击敌舰、收集经验、升级武器与船体，并面对精英敌舰和 Boss。

## 玩法概览

《海战霸主》采用**单局无尽生存**的 Roguelike 结构：

- 驾驶旗舰在半径 46 的海域中移动，主炮自动锁定并攻击射程内最近的目标；副炮、鱼雷与垂发导弹需要靠升级逐步装上。
- 击沉敌舰会掉落经验球，升级时从 3 项强化中选择 1 项；一次获得多级经验会连续进行多次选择。
- 玩家等级会改变旗舰外观，同时危险度会随时间提升，带来更强、更多的敌舰。
- 本局没有通关条件，旗舰耐久归零即结算；危险度到达第 6 阶段后不再提升，进入无限生存。

## 游戏模式与关卡节奏

游戏没有独立的关卡选择界面，而是用**危险度**划分一局内的 6 个阶段。危险度随存活时间自动提升，阶段越高，敌舰的生命、装甲、伤害、射速和经验奖励越高。

| 危险度 | 开始时间 | 生命倍率 | 额外装甲 | 伤害倍率 | 射击间隔倍率 | 经验倍率 | 普通敌舰同屏上限 | 刷新间隔 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 秒 | ×1.00 | +0 | ×1.00 | ×1.00 | ×1.00 | 5 | 4.5 秒 |
| 2 | 12 秒 | ×1.12 | +1 | ×1.06 | ×0.97 | ×1.08 | 6 | 4.2 秒 |
| 3 | 35 秒 | ×1.28 | +1 | ×1.13 | ×0.94 | ×1.16 | 7 | 3.9 秒 |
| 4 | 65 秒 | ×1.47 | +2 | ×1.21 | ×0.90 | ×1.26 | 8 | 3.6 秒 |
| 5 | 100 秒 | ×1.70 | +3 | ×1.30 | ×0.86 | ×1.36 | 9 | 3.3 秒 |
| 6 | 140 秒 | ×1.95 | +4 | ×1.40 | ×0.82 | ×1.48 | 10 | 3.0 秒 |

补充规则：

- 危险度只升不降，第 6 阶段之后保持该阶段数值，不会无限线性增长。
- 开局场上固定有 4 艘敌舰：突袭艇、鱼雷艇、炮艇、导弹艇。
- 普通敌舰的刷新遵循表中的同屏上限与刷新间隔；场上存在 Boss 时暂停普通增援。
- 每局只在**危险度 2（约 12 秒）**刷新 1 只 Boss“深海霸主”，击沉后本局不再出现。
- 旗舰耐久归零后进入结算，显示存活时间、击沉数、最高等级与 Boss 击杀数，可重新起航。

## 武器系统

四套武器独立冷却、独立索敌，全部自动开火，玩家只需专注于走位。**开局只有双联主炮**，其余三套要等到对应强化出现时才装上舰体。

| 武器 | 初始状态 | 射程 | 基础单发伤害 | 基础间隔 | 基础齐射 | 特点 |
| --- | --- | --- | --- | --- | --- | --- |
| 双联主炮 | 默认装备 | 29 | 12 | 0.85 秒 | 2 发 | 独立炮塔自动瞄准，炮管数量随旗舰进化增加，最多可使用 5 个炮口；弹道为抛物线 |
| 两舷副炮 | 需「副炮阵列」解锁 | 23 | 4（主炮伤害的 36%） | 0.52 秒 | 2 座各 1 发 | 左右独立炮塔，射速快、单发低 |
| 鱼雷发射器 | 需「鱼雷发射器」解锁 | 30 | 46 | 3.2 秒 | 1 发 | 慢速、高伤害，带航迹尾迹；Lv.3 起 2 发，Lv.5 起 3 发 |
| 垂直发射导弹 | 需「垂直导弹发射巢」解锁 | 34 | 30 | 2.8 秒 | 1 发 | 垂直升空 0.3 秒后转向追踪，拖出烟迹；命中造成 3.8 范围爆炸，55% 溅射伤害；最高 4 发齐射 |

武器强化：

- **主炮**通过通用强化提升单发伤害、射击间隔、齐射数量与射程。满强化可达单发 32、间隔约 0.45 秒、5 发齐射、射程 45。
- **副炮**通过「副炮阵列」强化解锁（Lv.1），可强化 3 次至 Lv.3；伤害同时受主炮伤害加成影响。
- **鱼雷**通过「鱼雷发射器」强化解锁（Lv.1），可强化 5 次至 Lv.5；满级单发 110、航速 21.6、间隔 2.72 秒、3 发齐射。
- **垂发导弹**通过「垂直导弹发射巢」强化解锁（Lv.1），可强化 5 次至 Lv.5；满级单发 78、间隔 2.0 秒、4 发齐射。

为了让一局不会长期只打主炮，只要还有武器没装上，每次升级的 3 张卡里就有一半概率直接出现一把武器解锁卡。

打击感与弹道：

- 主炮与副炮的炮弹走**抛物线弹道**（重力 14 单位/秒²）。开火时按目标水平距离与高度差解算仰角，飞行中炮弹沿速度方向翻转，因此远处目标会看到明显的抛射弧线。
- 每发炮弹都拖一条随时间淡出的**曳光尾迹**（导弹/鱼雷按历史位置绘制成曲线，转弯时尾迹也跟着弯）；导弹有排气烟迹，鱼雷有白色航迹。
- 命中会同时产生闪白、火花（带重力下坠）、水花与硝烟；鱼雷与导弹命中额外触发爆炸与轻微震屏，旗舰被击中时震屏最明显。
- 主炮开火带炮口硝烟与炮塔后坐（炮塔向后滑动再复位），开火瞬间有极轻微的画面抖动。

敌舰特点：

- **突袭艇**：基础快速炮艇，数量多，主要靠骚扰。
- **拦截艇**：速度最快，会贴近到近距离高频射击。
- **炮艇**：中距离稳定火力，装甲与耐久均衡。
- **鱼雷艇**：高速贴脸，单发鱼雷伤害高。
- **导弹艇**：双联导弹远程压制，射速较慢。
- **驱逐舰**：三联重炮，中远距离持续输出。
- **巡洋舰**：重甲高耐久，四联炮击，正面压制力强。
- **炮击舰**：超远射程重炮，会迫使玩家主动接近。
- **Boss 深海霸主**：双联主炮，并周期性释放带 1.5 秒预警圈的范围重炮（半径 5.5，伤害 24），需要及时驶出红圈。

精英变体：

- 出现概率从危险度 1 的 12% 开始，每提升 1 个危险度 +6%，最高 50%。
- 生命 ×1.6、装甲 +2、伤害 ×1.25、经验 ×2、体型 ×1.08。
- 带有金色光环与金色装甲饰条，血条变为金色。

## 成长与伤害规则

- 升级所需经验：`30 + (当前等级 - 1) × 20`。
- 玩家与敌舰受到的伤害均为 `max(1, 原始伤害 - 装甲)`。
- 击沉敌舰会生成经验球；靠近后自动吸附并拾取。
- 局内没有复活或额外生命机制；回复手段只有「应急维修」的击沉回血和「船体加固」的即时回复。
- 音效开关会保存在浏览器本地；游戏无永久角色成长。

## 本地运行

要求：Node.js 22 或更新版本，npm。

```bash
npm install
npm run dev
```

Vite 会输出本地访问地址，通常为 `http://localhost:5173/`。

生产构建与预览：

```bash
npm run build
npm run preview
```

测试：

```bash
npm test
```

## 操作

- 手机：左下角虚拟摇杆移动。
- 桌面：`WASD` 或方向键移动。
- 主炮自动锁定射程内最近目标并开火；装上副炮、鱼雷、垂发导弹后它们同样自动开火。
- 点击升级卡片选择强化。
- 右上角可切换基础音效开关；该偏好会保存在浏览器本地。
- 战船沉没后可点击“重新起航”。

## 构建产物

- 网页版构建：`npm run build`，输出 `dist/`。
- 小游戏构建：`npm run build:minigame`，输出 `minigame-dist/`（`game.js` + `game.json` + `project.config.json`）。
- 小游戏产物冒烟检查：`npm run smoke:minigame`；构建 + 冒烟 + 测试一条命令：`npm run verify:minigame`。
- 生产资源使用相对路径（`base: './'`），适配 Cloudflare Pages 根目录和子目录部署。
- 所有模型、纹理效果与音效均由代码生成；除站点图标外没有外部素材请求。
- 当前依赖只有运行时 `three`，开发依赖为 `vite`、`typescript`、`@types/three`、`vitest`。

## Cloudflare 部署

### 方式一：Cloudflare Workers 静态资源（本仓库已配置）

仓库包含 `wrangler.jsonc`，将 `dist/` 作为静态资源部署，不需要 `@cloudflare/vite-plugin`。

```bash
npx wrangler login
npm run deploy:dry-run
npm run deploy
```

- `npm run deploy` 会先执行 `npm run build`，再执行 `wrangler deploy`。
- `wrangler.jsonc` 已配置 SPA fallback：`not_found_handling: "single-page-application"`。
- 如果使用 `CLOUDFLARE_API_TOKEN`，可直接在 CI 中执行 `npm run deploy`。
- 已有 `wrangler.jsonc` 时，Cloudflare 的自动配置流程会跳过向 `vite.config.ts` 注入 Vite 插件的步骤。

### 方式二：Cloudflare Pages

1. 将项目推送到 Git 仓库并连接到 Cloudflare Pages。
2. 构建命令：`npm run build`
3. 构建输出目录：`dist`
4. Node 版本：`22.12.0` 或更新（仓库提供 `.node-version`；如平台未读取，设置环境变量 `NODE_VERSION=22.12.0`）。
5. 无需后端、环境变量或 SPA 重写规则；这是一个静态单页应用。

两种方式只需选择一种，不要同时启用。

### 关于自动配置报错

Cloudflare 的自动配置尝试向 Vite 配置注入 `@cloudflare/vite-plugin`。当前 `vite.config.ts` 导出的是函数式配置，旧版自动配置器无法解析其 `plugins` 字段，因此报错：

```text
Cannot modify Vite config: could not find a valid plugins array
```

本项目的构建产物完全是静态资源，不需要该插件。手动提供 `wrangler.jsonc` 后可直接部署，避免自动改写 Vite 配置。

## 平台边界

平台相关能力通过以下接口隔离：

- `src/platform/PlatformAdapter.ts`
  - `PlatformAdapter`：输入创建、存储、暂停/恢复、销毁。
  - `InputSource`：摇杆/键盘等输入源统一接口。
  - `KeyValueStorage`：可替换的键值存储接口。
- `src/platform/WebPlatform.ts`：浏览器实现，使用 Pointer Events、`localStorage` 和 `visibilitychange`。
- `src/input/InputManager.ts`：Web 输入实现，注入到游戏逻辑。
- `src/audio/SoundManager.ts`：独立的 Web Audio 合成音效层，不加载外部音频文件。

游戏逻辑不再直接读写浏览器存储或页面可见性。

## 抖音小游戏版本

网页版与抖音小游戏版**共用同一套游戏逻辑，各用独立入口**。网页版入口（`index.html` + `src/main.ts`）不变，小游戏版新增在 `src/minigame/` 下，两者互不引用。

| 项目 | 网页版 | 抖音小游戏版 |
| --- | --- | --- |
| 入口 | `index.html` + `src/main.ts` | `src/minigame/main.ts` |
| 构建 | `npm run build` → `dist/` | `npm run build:minigame` → `minigame-dist/` |
| 渲染载体 | DOM + CSS HUD | 一块屏幕画布 + 2D 合成 HUD |
| 输入 | Pointer Events / 键盘 | `tt.onTouchStart` 等触摸事件 |
| 存储 | `localStorage` | `tt.setStorageSync` |
| 暂停恢复 | `visibilitychange` | `tt.onShow` / `tt.onHide` |
| 声音 | Web Audio | `tt.createWebAudioContext`，不可用时静默 |

小游戏版通过 `PlatformAdapter` 接入，`src/game/` 里没有任何平台判断：

- `src/minigame/main.ts`：创建屏幕画布与离屏 WebGL 画布，每帧把 3D 画面合成到 2D HUD 下方。
- `src/minigame/MiniGameUi.ts`：Canvas HUD、虚拟摇杆、升级卡片与结算面板，实现与网页 HUD 相同的 `GameHud` 接口。
  摇杆是“全屏浮动”式：手指按在屏幕任何位置，就在按下的地方生成基座并开始转向，不必去找固定的左下角摇杆（音效按钮占用的区域除外）。
- `src/platform/MiniGamePlatform.ts`：`tt` 存储、生命周期与输入注入。
- `src/minigame/runtime.ts`：只声明本项目用到的 `tt` 接口，网页构建不依赖小游戏类型。

### 已验证 / 未验证

已验证（本机可复现）：

- `npm run build:minigame` 通过，产物 `minigame-dist/game.js` 约 695 KB（gzip 179 KB），并复制 `game.json`、`project.config.json`。
- 产物在无 DOM、无 WebGL 的模拟运行时（`npm run smoke:minigame`）中能加载：创建两块画布、注册四个触摸回调与 `onShow/onHide`、读取屏幕信息；WebGL 不可用时画出错误提示页，而不是白屏。
- 18 个测试文件、104 个用例通过，其中 `tests/minigameUi.test.ts`、`tests/minigamePlatform.test.ts` 覆盖摇杆死区与边界、选卡、结算重开、音效按钮、存储回退、暂停恢复；`tests/ballistics.test.ts` 覆盖抛物弹道解算、曳光尾迹与尾迹清理。

未验证（不要当成已兼容）：

- 没有在抖音开发者工具里导入运行过。
- 没有真机数据：帧率、发热、触控手感、前后台切换均未测量。
- 音频链路未验证：代码只在 `tt.createWebAudioContext` 存在时出声，否则静默。
- 最关键的未知项：three.js 需要 **WebGL2**，目标设备与运行时是否提供、当前着色器能否编译，必须上机确认。

### 导入抖音开发者工具

1. 把 `minigame/project.config.json` 的 `appid` 换成自己的小游戏 AppID
2. 执行 `npm run build:minigame`
3. 确认 `minigame-dist/` 里只有 `game.js`、`game.json`、`project.config.json` 三个文件
4. 开发者工具选择「导入项目」，目录选 `minigame-dist/`，项目类型选「小游戏」，编译

> 开发者工具会编译它扫到的每一个 `.js`。`minigame-dist/` 是构建产物，不要往里放模板解压包或任何手工文件——macOS 的 `__MACOSX/._*.js` 会被当成 JS 解析并报 `SyntaxError: Unexpected character 'u{5}'`。构建脚本会自动清掉杂散文件并打印 `Removed unexpected entry`。

逐项上机验证清单见 `docs/minigame-verify.md`。

## 已知限制

- 未在真实手机上进行最终性能与触控测试。
