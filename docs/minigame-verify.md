# 抖音小游戏上机验证清单

这份清单只解决一个问题：**`minigame-dist/` 到底能不能在抖音里跑起来。**

现在能证明的只有三件事：构建通过、产物在模拟运行时能加载、逻辑测试通过。**没有一件事能证明它在真机上能玩。** 下面每一项都要在开发者工具或真机上实际看到结果才能打勾；没跑过的项就写「未验证」，不要按经验推断。

## 前置

1. `appid` 已填为 `ttdac6ac7b44bfbc0f02`（源头是 `minigame/project.config.json`，构建时复制进 `minigame-dist/`）。如果开发者工具打开项目后自己改写了这个字段，记得同步回源文件，否则下次构建会被覆盖。
2. `npm run build:minigame`
3. 确认 `minigame-dist/` 里**只有三个文件**：`game.js`、`game.json`、`project.config.json`。
4. 开发者工具「导入项目」，目录选 `minigame-dist/`，项目类型选「小游戏」。

### 导入的目录必须是干净的

开发者工具会把它扫到的**每一个 `.js`** 都拿去编译，包括不是我们写的那些。

实际踩过的坑：`__MACOSX/template/_game.js` 报 `SyntaxError: Unexpected character 'u{5}'`。那不是代码错误——是 macOS 打 zip 时留下的 AppleDouble 元数据（文件头 `00 05 16 07`，内容是 `Mac OS X`、`com.apple.*` 之类的二进制），被当成 JS 解析了。同类问题还有：把官方小游戏模板压缩包直接解压进 `minigame-dist/`，会多出一个 `海战/game.js`（926 字节的空白模板），同样会被一起编译。

`npm run build:minigame` 现在会自动删掉这些杂散文件，并打印 `Removed unexpected entry from minigame-dist/: xxx`。看到这行就说明目录被污染过，删完即恢复。**不要手工往 `minigame-dist/` 里放任何东西**，它是构建产物，每次构建都会被重建。

## 卡顿时可调的旋钮

先记录现象（第几分钟开始卡、什么场景卡），再动这些参数，一次只改一项：

| 想降低的负载 | 改哪里 | 说明 |
| --- | --- | --- |
| 阴影开销 | `src/game/SceneManager.ts` 的 `shadowMapSize` 选项（小游戏入口传 1024） | 降到 512 或关掉阴影最省，画面会明显变平 |
| 分辨率 | `src/minigame/main.ts` 的 `maxPixelRatio`（现在跟随设备 pixelRatio，上限 3） | **这是清晰度的主开关**。降到 2 大约省 55% 填充率，但仍然锐利；降到 1.5 就会开始糊 |
| 抗锯齿 | `src/game/SceneManager.ts` 的 `antialias` 选项（小游戏入口已关） | 网页版仍开启，小游戏靠像素比补偿 |
| 画质下限 | `adaptQuality()` 里的 0.66 下限与升降阈值 | 下限越低越流畅，但低端机可能明显糊 |

`shadowMapSize` / `antialias` / `maxPixelRatio` 都从小游戏入口传入，改它们不会影响网页版。
